01首次启动向导 · 交互式复刻

桌面端第一次打开时，窗口里并没有工作区界面，而是一个原生欢迎窗口——它只做一件事：确认你用什么凭据调用模型（登录 DeepSeek 账号，或填一个 API Key）。凭据确定后，才会出现真正的引导页，问你「你希望 DeepSeek Harness 帮你做什么？」。

先走一遍，再决定装不装

下面的流程完全按 0.2.0-rc.2 的真实顺序和真实文案复刻。走完之后你就知道每个选项意味着什么、会改掉哪些设置，不会装完了才发现选错。

欢迎

🧭 这个向导回答什么

  • 用账号登录还是填 API Key
  • 余额和「去充值」是什么关系
  • 「办公与创作」和「代码与开发」到底改了什么
  • 「你想看到多少工作过程」三档的区别

🚫 这个向导不做什么

  • 不会创建工作区。工作区是你装完第一小时自己选的。
  • 不会创建示例任务。第一个任务得你自己下。
  • 不配置权限模式。权限在会话里单独切换。

🔁 选错了怎么办

  • 进度存在本机，可以「上一步」回去改。
  • 「跳过」以后，当前安装不再自动重跑这个流程。
  • 完成或跳过之后，所有选项都能在设置里改回来。
  • 想做代码相关的事，去 设置 → 通用设置 打开 「显示代码工作视图」（开启后会显示轨迹、本轮代码差异，并可切换完整的 Agent 预设）。

一个容易被忽略的坑

桌面端只能同时运行一个 DSH。如果你之前开过 dsh web 或另一个桌面窗口，启动会直接失败并提示「有其他正在运行的 DSH……请退出其他正在运行的 DSH 后重启」。这不是装坏了，先把旧的关掉就行。

03装完之后的第一小时

官方指南讲到「首次启动」就停了，而新手真正卡住的地方恰好从这里开始。这一节按你实际会看到的屏幕顺序给出四个决定。

3.1 第一件事：工作区选哪个目录

打开桌面端后，你会看到一个空的工作区列表和一句提示：「选择工作区」。工作区就是 Agent 的「活动范围」——它默认只能在这里面读写文件。

DSH 自己会先建一个默认工作区

如果这是全新安装，DSH 会主动创建并选中一个默认工作区，路径是固定的：

%USERPROFILE%\Documents\deepseek-harness\default-workspace

在中文 Windows 上就是「文档」文件夹，整体形如 C:\Users\你的名字\Documents\deepseek-harness\default-workspace。这个名字是语言无关的固定值，切换界面语言不会变成第二个目录。

建议：新建一个专门的测试文件夹，别直接用默认那个

默认工作区在「文档」目录下，离你的毕业论文、合同、报税表只有一层之隔。新手期建议自己建一个一次性的测试目录，例如 D:\dsh-试试，专门用来熟悉它。等你确定它能干什么、不能干什么，再把它指到真正的项目目录。

选哪种目录适不适合新手为什么
专门新建的测试文件夹推荐随便它折腾，删掉也不心疼。适合建立信任。
代码项目 / Git 仓库推荐有版本控制兜底，改错了 git checkout 就能回滚。桌面端自带代码工作视图。
桌面 / 文档根目录不建议文件又多又杂，且往往是唯一副本。一旦误删很难恢复。
整个 C 盘或用户主目录不要等于把系统盘交给它。这不是设计用途。
OneDrive / 网盘同步目录谨慎同步进程 + Agent 同时改文件容易冲突。要试就先用小目录。

工作区可以随时新增、重命名、排序、删除。删除一个工作区不会删掉里面的文件，只是不再把它列出来。

3.2 第二件事：权限给多少

会话里有一个「权限」控件，它把沙箱模式和审批策略两个开关捆成一个选项给你选。新会话默认用哪一种，可以在设置里定。详细对比在第 4 节，这里先记住结论：

  • 头几天用 「工作区内修改」（已包含在默认预设里）——够用，且有边界。
  • 想要最保守，切到 「仅可查看」，让它先只读不写。
  • 「完全权限」需要你勾一段风险确认才会打开。新手期不建议。

3.3 第三件事：模型怎么配

好消息：如果你在欢迎窗口登录了 DeepSeek 账号，这一步基本不用做。登录成功后，DSH 会自动把 deepseek-account 下第一个可用模型设为默认模型，你直接就能开始提问。

只有这几种情况才需要手动配：

  • 你在欢迎窗口选了「添加 API Key」，那就要把 Key 填进去；
  • 你想用第三方模型（OpenAI 兼容、Anthropic 协议、自部署服务）；
  • 你想换默认模型或调推理强度。

具体路径见第 5 节。

3.4 第四件事：第一个任务做什么

新手第一个任务不该是「帮我重写整个项目」，而应该是一件你能一眼判断对错的小事。见第 6 节的三个现成示例。

04权限到底给多少（含原始文案）

DSH 的文件权限只有三个档位，界面上的名字和它们的真实含义如下。这里的文案是 0.2.0-rc.2 客户端里的原文，你在界面上看到的就是这些字。

仅可查看 最安全

read-only

能读文件、能分析、能给出方案，但不能改任何文件。模型的系统提示里会明确写上「本次为只读模式」。

适合：第一次试用、让它看一份不该被改的资料。

工作区内修改 推荐

workspace-write

只能改当前工作区目录里的文件，工作区外一律碰不到。需要动外面的东西时会向你申请。

适合：日常使用。边界清晰，能干活。

完全权限 高风险

danger-full-access

文件沙箱完全不限制修改范围，并且确认步骤会明显减少。选它时会弹出风险确认。

适合：你已经非常清楚自己在做什么的时候。

选「完全权限」时它会说什么

DSH 不会默默放开权限，它会先弹一个确认框，原文如下：

确认启用完全权限？

「启用完全权限后，新会话将减少确认步骤，并且可以直接执行更多操作，包括敏感操作、文件修改或外部命令。仅建议在你信任后续任务时使用。」

按钮：我已了解风险，并愿意继续 / 取消 / 启用完全权限

沙箱管的是「文件」，不是「网络」

这三档只控制文件修改的范围。它不限制联网，也不限制执行命令这件事本身。所以「工作区内修改」不等于「绝对安全」——它只保证你的工作区之外的文件不会被它改掉。

三个关键性质

  • 按会话生效：权限是每个会话各自的，A 会话放开不会影响 B 会话；切换记录会写进会话日志，重启后按日志恢复。
  • 写进日志可追溯：每次切换都是会话日志里的一条事件，事后能查。
  • 审批不等于改权限：你在某个操作上点了「允许」，只是放行这一次，不会把整个会话的权限模式改掉。

05模型怎么配

先说结论：用 DeepSeek 账号登录的话，通常一个字都不用填。下面分「自动的」和「手动的」两部分。

5.1 什么都不用做的情况

你在欢迎窗口点了 「登录」并用 DeepSeek 账号完成授权。登录成功后，如果其他提供方都没有配 Key，DSH 会把 deepseek-account 的第一个可用模型设为默认模型——即使你以前保存过别的默认选择。你要做的就是直接开聊。

注意：只要你给任何一个其他提供方配过 Key，它就会尊重你原来的默认选择，不会覆盖。

5.2 手动配置的入口

打开 设置 → 模型（桌面端快捷键 Mod+, 打开设置）。页面按「提供方」一行一行列出来，一次只展开一张编辑卡：

你要做的事在页面上点哪里
填 / 换 DeepSeek API Key在 DeepSeek 那一行的编辑卡片里，只有一个 API 密钥 输入框
改模型列表、上下文窗口、输入类型展开 自定义设置 → 模型选项 编辑模型行
接第三方模型添加模型提供商 → 选「第三方模型提供商」
接中转站 / 自部署服务添加模型提供商 → 选「自定义模型 API」，填 Provider ID、端点、协议
换当前会话用的模型直接在输入框上方的模型选择器里切

Key 存在哪、会不会泄漏到配置文件里

你输入的 API 密钥是只写保存的：它以「凭据引用」的方式存进当前 profile 的凭据存储，不会写进 cordis.patch.yml。也就是说，你把配置文件发给别人，不会连带把 Key 发出去。已配置的引用只显示状态点（绿点=已配置，红点=引用缺失），界面不会回显密钥内容。

5.3 默认模型改在哪

默认模型是一项普通配置。你可以在设置界面里选，也可以直接编辑 profile 的补丁文件 %USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml，找到这一段：

- id: agent-default-model
  name: "@deepseek-ai/dsh-agent-default-model"
  config:
    provider: deepseek-account
    model: deepseek-flash
    reasoningEffort: high

桌面的设置面板里有「打开配置文件」入口，可以直接用系统默认编辑器打开它。手改之前建议先备份。

06第一个任务做什么

挑第一个任务的标准只有一条：你能在 10 秒内判断结果对不对。别一上来就让它重构项目。

① 只读侦察（零风险）

权限：仅可查看

先让它只看不动，你会直观感受到「它能读到什么」。

把这个文件夹里有什么、每个文件大概是干什么的，整理成一份清单给我。不要修改任何文件。

② 造一个新文件（可控）

权限：工作区内修改

输出物是一个全新文件，不碰你任何已有数据。

新建一个 todo.md，写一个「三天内熟悉 DSH」的清单，每条不超过一行。

③ 办公创作类（对齐向导选项）

权限：工作区内修改

桌面端自带 Office 能力，可以在本地直接产出文档。

把这个目录里的数据整理成一张表格，另存为一个新的 xlsx，并告诉我你做了哪些处理。

看懂第一轮再放手

第一轮里重点看两件事：它读/写了哪些文件（工具调用会列出来），以及它有没有在你没要求的地方动手。确认这两点符合预期，再让它做更大的事。

输入框旁边那些符号

  • / —— 打开命令菜单（斜杠命令）。
  • @ —— 引用文件或对话。
  • 拖动文件或图片进输入框即可作为附件。
  • 桌面端额外支持直接拖入整个文件夹（浏览器里只能拖单个文件）。

07桌面端特有的 5 件事

这五件事在 Web 版和命令行里不存在或不一样。它们是桌面端新手最容易误解的地方，也是后面插件推荐的前提。

7.1 关掉窗口 ≠ 退出程序

点关闭按钮时，正在跑的任务不会中断。真实提示原文是：

「正在运行的任务不会中断，可在系统托盘中重新打开窗口」

窗口只是收进系统托盘，Agent 继续干活。想继续看，从托盘点回来即可。

7.2 真正「退出」时它会拦住你

选择「退出 DeepSeek Harness」时，它会先检查有没有活儿在跑，然后按情况给不同警告（均为原文）：

退出对话框文案触发条件
当前正在运行的任务将会中断有正在生成的 Agent、正在跑的工具、排队中的消息，或有运行中的后台任务
应用关闭期间，定时任务不会运行有已启用的定时任务（这些任务需要 App 在运行）
当前正在运行的任务将会中断，且应用关闭期间，定时任务不会运行两者同时存在

含义：关窗口是安全的，退出程序不是。有活在跑时，直接退出会让它断掉。

7.3 后台任务面板：任务的唯一权威列表

会话头部有一个后台任务控件。只有当前会话真的产生过后台任务，它才会出现。

你看到的状态含义
运行中 / 正在停止任务还在跑
已完成 / 已失败 / 已取消任务的终态
「{n} 个后台任务运行中」头部计数，一眼可见还有几个在跑
「已运行 3分20秒」/「耗时 3分20秒」进行中显示已运行时长，结束后显示总耗时

展开一行可以看实时输出，收起就停流；跑着的行有一个两击式停止按钮——第一下是「武装」，第二下确认才会真的杀掉任务。这样做是为了防误触。

停止一个任务时，Agent 会收到明确通知「用户停止了你的任务」，而不是自己猜。所以你可以放心点停止，它不会以为任务成功了。

7.4 和命令行共用同一个家目录

桌面端和 dsh 命令行读的是同一个 %USERPROFILE%\.dsh。这意味着：

  • 好处：会话记录、工作区注册表是共享的，两边能看到同一批历史。
  • 限制：不能同时运行。桌面端占用了固定端口，另一个实例启动时会直接报「有其他正在运行的 DSH（如其他 dsh web、桌面端），无法同时启动」。

数据共享 ≠ 实时同步

两边是同一份数据，不是两份数据互相同步。所以不存在「桌面端改了、命令行没更新」这种冲突——但这也意味着，在一边打开着会话的时候从另一边操作同一个会话，行为要自己注意。稳妥做法：同一时间只用一个入口。

7.5 桌面端还能把 dsh 命令装进终端

菜单里有 管理 dsh 命令，可以把 dsh 注册到你的终端，之后就能在任意终端里直接敲 dsh。它也会管理、修复、移除这个注册（会保留原有的启动器备份）。

同一菜单里还有一个「禁用第三方插件、备份 profile patch 并重启」的恢复项。装插件把界面搞崩了的时候，这是最省事的自救按钮。

09安全注意事项（人话版）

官方的 SAFETY 文档是法律和工程层面的声明，读起来像免责条款。这里把它翻译成具体能照做的操作规则。

最重要的一句话

DSH 官方自己的说法是：「尚未接受安全审计，不得视为安全或可用于生产环境的软件」。所以正确的心态是——把它当成一个能力很强但需要你看着的新同事，而不是一个可以完全托管的工具。

9.1 该做 / 不该做

✅ 这样做

  • 第一次用，工作区专门新建一个测试文件夹，不要选桌面或文档目录。
  • 权限先给「仅可查看」，用几天确认没问题再放开到「工作区内修改」。
  • 插件装之前先看下载量，别装刚发出来的、没人用过的包。
  • 重要目录先放一份备份或纳入 Git，再让它动手。
  • 让它做批量修改前后，看一眼它列出的文件清单。
  • 只在一个入口操作（桌面端或命令行，二选一）。
  • 把长期任务写成文件放进工作区，而不是指望记住。

⛔ 别这样做

  • 别把工作区设成整个 C 盘、用户主目录或系统目录。
  • 别一上手就开「完全权限」——它连确认都在减少。
  • 别在唯一一份重要文件所在的目录里直接跑批量任务。
  • 别把 API Key、密码、身份证照片放进工作区。
  • 别在任务运行中直接退出程序（关窗口没事）。
  • 别装来源不明的插件——它们在宿主进程里运行，不受工作区沙箱限制。
  • 别同时开两个 DSH 实例，会冲突。

9.2 为什么插件比文件更危险

这是整个安全模型里最反直觉的一点：

你在工作区里跑 Agent 时，文件沙箱会把它的写入限制在工作区内。但插件是宿主进程的一部分——它的代码在工作区沙箱之外运行，可以读写你的整个用户目录、执行命令、发网络请求。

而且插件是跨会话持久生效的：装上以后，之后每个会话都受它影响，不只当前这一个。

所以官方在插件管理上的措辞很谨慎：每个安装动作都要求「完全权限」或当次明确批准；批准只放行这一次，不会改变会话的权限模式。如果你的沙箱模式比较严，装插件时就会弹审批——那是设计如此，不是出错了。

9.3 装插件前的 30 秒检查

  1. 下载量：npm 周下载量有几千以上吗？几百甚至个位数要格外小心。
  2. 发布时间：刚发出来几天的版本，先等一等。刚发布的包出问题是常态。
  3. 它声明了 DSH 版本要求吗：有 engines.dsh / peer 约束的包，说明作者认真适配过当前版本。
  4. 它要干什么：如果一个「美化插件」要求你的文件权限或密钥访问，直接放弃。
  5. 有没有构建脚本：安装时若提示「允许这些脚本并重试」——那意味着要执行它带来的代码。看不懂就别允许。
  6. 出问题能退吗：桌面端菜单里的「禁用第三方插件、备份 profile patch 并重启」是你的后悔药。

9.4 出事了怎么办

症状先做这个
装完插件后界面打不开 / 一直崩用菜单里的「禁用第三方插件、备份 profile patch 并重启」；它会把插件配置备份后禁用，然后重启
它改了不该改的文件先在会话里往回翻它列出的文件清单；有 Git 就 git checkout，没有就用回收站 / 备份恢复。之后把权限降到「仅可查看」
启动报「有其他正在运行的 DSH」把另一个 dsh web 或桌面窗口关掉再启动。这是端口冲突，不是安装损坏
不确定某种操作安不安全先在一个新建的测试工作区里试一次。这是成本最低的验证方式
任务卡住停不下来用后台任务面板那个两击式停止按钮；不要靠直接退出程序

10插件推荐 · 桌面版特供

先说三件必须说清楚的事，因为它直接影响你会不会装错东西。

正在流传的新手插件组合里，有两个包名是错的

面向 Web/CLI 用户推荐的那套「dsh-market + dsh-at-file + ModLens」中：

  • dsh-market —— npm 上没有这个包。它是 GitHub 仓库/组织名。真正的包叫 dshmarket。
  • ModLens / modlens —— npm 上都没有。真正的包叫 @liustack/modlens。
  • dsh-at-file —— ✅ 名字是对的。

照错名字去装，要么装不上，要么可能在 npm 上撞到别人抢注的同名包。下面的包名都逐个查过 npm registry。

关于「桌面版实测可用」这句标注

我把它拆成了两档，因为诚实比一句话更有用：

  • 已在本机桌面端安装 —— 我直接读了你机器上 %USERPROFILE%\.dsh\profiles\desktop\package.json，确认它就在 dsh.profile.bundles 里。
  • 已声明兼容当前版本 —— 包的元数据里有指向 0.2.0-rc.2 的版本约束，说明作者适配过。这不等于我替你装过并且跑通了。

没有任何一个第三方插件我能替你保证「一定装得上、一定跑得通」——那需要在你的机器上真的装一次。安装前请按 9.3 的 30 秒检查过一遍。

先纠正一个预期：桌面端最痛的那件事，没有插件能解决

「窗口关了任务还在跑」「后台任务怎么管」——这两个问题桌面端自己已经解决了，不需要插件：任务面板是内置的，关窗口不中断任务是内置的，退出时的拦截也是内置的。第三方插件在这里帮不上更大的忙。

另外，我没有找到任何插件的用途是「让桌面端和命令行共享数据」——因为那本来就不需要插件：两者共用同一个 ~/.dsh。真正需要注意的是「不能同时运行」，也不是插件能解决的。

10.4 装插件的三条纪律

  1. 一次只装一个。装完确认界面正常、开一个新会话能跑，再装下一个。一次装五个，出问题你不知道是谁的。
  2. 别被名字骗了。npm 上抢注同名包很常见。像 dsh-market 这种「看起来就该存在」但实际不存在的名字，正是最容易踩的坑。
  3. 记得你有后悔药。桌面端菜单里的「禁用第三方插件、备份 profile patch 并重启」可以在界面坏掉时救命。装之前知道它在哪，比事后找它有用。

一句话总结插件部分

桌面端的痛点大多由应用本身解决了（后台任务面板、关窗口不中断、退出拦截、与命令行共享 ~/.dsh）。真正值得装的插件只有三类：花钱看得见（余额挂件）、装起来方便（市场）、跑完了叫你（通知）。其他的按需再说。

新手期最常犯的 5 个错

  1. 工作区用了文档目录，然后让它批量改文件。
  2. 一上手就开完全权限，跳过了观察它行为的阶段。
  3. 照流传的插件名装，而其中 dsh-market、ModLens 在 npm 上并不存在。
  4. 任务在跑时直接退出程序，把活儿打断了（关窗口是安全的）。
  5. 同时开桌面端和命令行，撞端口启动失败，以为装坏了。
