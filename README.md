# DeepSeek Harness 桌面端 · 小白从零上手指南

一份**面向完全新手**的 DeepSeek Harness（dsh）桌面端上手教程，单文件 HTML，可离线打开。

它想解决的，是官方指南没说清的四个问题：

| # | 问题 | 这一页给出的东西 |
|---|---|---|
| 1 | 首次启动向导到底会问什么？ | **交互式复刻**：可以反复走一遍真实流程，再决定装不装 |
| 2 | 装完之后那一小时该做什么？ | 六步**确认式**安装 + 12 项**可勾选**的装完后检查清单 |
| 3 | 安全声明看不懂 | 把 `SAFETY` 的法律/工程声明翻译成**能照做的操作规则** |
| 4 | 插件该装哪些？ | 逐个查过 npm registry 的**桌面端**推荐，分用途、标注可信度 |

## 打开方式

直接双击 `dsh-desktop-新手从零上手指南.html`，或用浏览器打开。**无需联网、无需服务器、无外部依赖**（样式与脚本全部内联，图标是内联 SVG）。

深色 / 浅色主题会跟随系统，也可以手动切换。安装进度和检查清单的勾选状态存在浏览器 `localStorage` 里，关掉再打开还在。

## 这份教程的取材方式

界面文案、权限模式、默认工作区路径、后台任务行为、退出拦截规则、插件安装规则，都取自本机安装的 **DeepSeek Harness `0.2.0-rc.2`** 实际文件，**逐字核对**而非改写：

- 客户端文案字典（如用途卡片 `办公与创作` / `代码与开发`、过程三档 `聚焦结果` / `关键细节` / `完整过程`）
- 权限预设文案（`仅可查看` / `工作区内修改` / `完全权限` 及风险确认原文）
- 桌面壳的退出与托盘提示原文
- 默认工作区的构造逻辑（`<文档>\deepseek-harness\default-workspace`，语言无关的固定值）
- 插件管理器的兼容性检查与构建脚本批准规则

插件部分逐个查询了 npm registry 的真实包名、版本与周下载量。

## 两个必须纠正的常见错误

流传的「新手插件组合 `dsh-market` + `dsh-at-file` + `ModLens`」里，**有两个包名在 npm 上不存在**：

| 流传的名字 | 真相 |
|---|---|
| `dsh-market` | **npm 上不存在**，它是 GitHub 仓库/组织名。真正的包是 **`dshmarket`** |
| `ModLens` / `modlens` | **都不存在**。真正的包是 **`@liustack/modlens`** |
| `dsh-at-file` | ✅ 名字正确 |

照错名字去装，要么装不上，要么可能在 npm 上撞到别人抢注的同名包。**这也是本仓库存在的意义之一**：新手教程里的包名必须能被验证。

## 一个重要的预期修正

**桌面端最痛的那件事，没有插件能解决。** 「窗口关了任务还在跑」「后台任务怎么管」是**应用内置**能力：

- 关窗口只是收进系统托盘，任务继续（原文提示：「正在运行的任务不会中断，可在系统托盘中重新打开窗口」）
- 后台任务面板是内置的，带实时输出与两击式停止
- 退出程序前会检查并拦截：「当前正在运行的任务将会中断」/「应用关闭期间，定时任务不会运行」

同样，**没有插件**的用途是「让桌面端和命令行共享数据」——因为两者本来就共用 `%USERPROFILE%\.dsh`。真正需要注意的是**不能同时运行**（端口冲突）。

所以插件推荐只聚焦三类精华：**花钱看得见**、**装起来方便**、**跑完了叫你**。

## 可信度标注

教程里对插件刻意分了两档标注，而不是笼统写「实测可用」：

- **已在本机桌面端安装** — 有实际安装记录可查（`dsh-whale-widget`）
- **已声明兼容当前版本** — 包的元数据里有指向 `0.2.0-rc.2` 的版本约束

**没有任何第三方插件被保证「装得上、跑得通」**——那需要在你的机器上真的装一次。安装前请按教程里的「30 秒检查」自己过一遍。
